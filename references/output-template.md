# 输出模板与邮件写作规则

## 输出结构

```markdown
# <客户>：跟进建议与邮件草稿

文件头：保密等级、关联战役或商机、资料来源、起草人和日期

## 一句话结论
现状如何，本期可能性多大，这周能做的那一步是什么，目的是什么

## 1. 上次接触（时间线表）
## 2. 卡点（每条标明事实或判断）
## 3. 他们的近况（公开信息表，加关联点）
## 4. 建议的一步（含发之前的内部确认、没有回音时的后手、止损点）
## 5. 英文邮件草稿（含中文对照和写作说明）
## 6. 需要决策人决定的事
## 7. 数据缺口（没查到、没核对的，逐条列出）
```

## 英文邮件结构

1. **开头**：用对方的公开进展或业务关联点引入，一段。个人敏感信息（离职、人事变动）不写进邮件。
2. **为什么写这封信**：一句话，落在"让我们更好地支持你们"上。
3. **2～3 个编号的问题**，每个问题都要有目的：
   - 确认现状：已经在用的产品运行得怎么样，有没有要改进的地方
   - 排除风险：后面的项目还用不用我们的产品，方案有没有变
   - 给对方一个提前沟通的理由：比如"早点告诉我们，定制和生产能提前排"
4. **一个小请求**：比如"两周内约 20 分钟电话"，或者"如果现在不是你负责，请转给合适的人"。对接人不清楚时，先确认对接人，再问需求。
5. **署名**。

## 邮件规则

- 不写价格、折扣、付款条件和交期承诺。
- 不写任何第三方伙伴的数据或名字。
- 不写安全漏洞细节，只说 "security-related updates"。
- 引用公开新闻只用已经核对过的。
- 全文控制在 150～200 个英文词。
- 邮件后面附一段"写作说明"：为什么这样开头，每个问题想确认什么。

## 自查清单（交稿前逐条过一遍）

- [ ] 已发送邮件查过了吗？有没有把"我们没回"误判成"对方没回"？
- [ ] 每个判断都写了依据吗？
- [ ] 公开信息都带链接、标了状态吗？没核对的有没有写进邮件？
- [ ] 至少找到一个关联点，排查了一个风险吗？
- [ ] 下一步写清楚人、日期、收件人和抄送了吗？有没有止损点？
- [ ] 邮件里有没有价格、付款条件、交期承诺、第三方数据或漏洞细节？
- [ ] 这个客户和哪些伙伴有渠道冲突或保密要求？这些名字在邮件里一律不出现，反过来写给那些伙伴的邮件里也不提这个客户。
- [ ] 跟踪表、战役卡里和原始记录对不上的地方，列出来了吗？
- [ ] 判断了跟进类型（①②③）吗？开头和问题跟类型对得上吗？
- [ ] 收件人至少列了两个方案，每个都写了风险吗？
- [ ] 数据缺口列全了吗？

## 常见错误

- 一上来就写邮件，没查历史，结果把对方早就回绝过的事又问一遍。
- 只看收件箱，不看已发送和内部群聊，把同事已经跟过的事当成没人跟。
- 拿跟踪表里占位的预测金额当真实需求。
- 用 "Just following up" 或 "Any update?" 开头。
- 公开新闻没打开原文就引用，弄错了很尴尬。
- 下一步写成"保持跟进"，没有日期，也没有止损点。
